# 驱动协议与单位

## 零差云控 eRob

实现文件：`App/Src/erob_canopen.c` 和 `App/Inc/erob_canopen.h`。

依据工作区中的《eRob CANopen and EtherCAT User Manual V1.5》。驱动使用标准 11 位 CANopen 帧：NMT `0x000`、客户端 SDO `0x600 + node`、服务端 SDO `0x580 + node`，支持 1/2/4 字节快速 SDO 和 abort code 解析。

已封装对象：

| 对象 | 用途 | 单位 |
| --- | --- | --- |
| `0x6040` | 控制字 | CiA 402 bit field |
| `0x6041` | 状态字 | CiA 402 bit field |
| `0x6060` | 运行模式 | 1=PP，3=PV，4=PT，7/8/9/10=同步模式 |
| `0x607A` | 目标位置 | plus（编码器计数） |
| `0x60FF` | 目标速度 | plus/s |
| `0x6071` | 目标转矩 | 额定电流千分比，不是 N·m |
| `0x6081` | 轮廓速度 | plus/s |
| `0x6083/0x6084` | 轮廓加/减速度 | plus/s^2 |

UDP 使能先发送控制字 6，在未使能状态切到 PV 模式并把目标速度写 0，再发送控制字 7、15，避免电机沿用断电前的模式或非零目标。手册要求伺服使能后至少等待 500 ms 才发送运动命令；应用层除强制稳定期外，还要求收到 250 ms 内且状态为 `OPERATION_ENABLED` 的状态字，否则拒绝运动并快速停机。重复 ENABLE 会重新开始计时并使旧状态失效。每条位置命令先写 `0x000F` 再写 `0x001F`，以形成 bit4 上升沿并触发新设定点。实际每转 plus 数、方向、软件位置限制和额定电流必须从具体 eRob 型号参数取得，固件不猜测机械换算。

CAN1 当前为 1 Mbit/s。若实物 eRob 的 CANopen 波特率不同，应修改 `Core/Src/board.c` 的 CAN1 timing，不能只改文档。

## 灵足时代 RobStride

实现文件：`App/Src/robstride.c` 和 `App/Inc/robstride.h`。

协议依据：

- 官方产品资料库：<https://github.com/RobStride/Product_Information>
- 官方 STM32 示例：<https://github.com/RobStride/RobStrideSPC>
- RS01 当前中文手册目录：<https://github.com/RobStride/Product_Information/tree/main/%E4%BA%A7%E5%93%81%E8%B5%84%E6%96%99/RS01>

官方 STM32 示例在每次类型 18 参数写入后保留 `1 ms` 间隔。本工程的整机桥接也遵循该时序；延时只发生在 RobStride 参数命令序列中，USART6 循环 DMA 在此期间仍持续接收力数据。

使用 CAN 2.0、1 Mbit/s、29 位扩展帧。扩展 ID 为：

```text
(communication_type << 24) | (data_field << 8) | target_id
```

主机 ID 默认 `0xFD`。实现的通信类型：0 发现、1 运控、2 反馈、3 使能、4 停止/版本读取、6 设零、7 修改 ID、17 读参数、18 写参数、21 故障、22 保存、23 波特率、24 主动上报、25 协议切换。

运控帧的 position/velocity/kp/kd 和扩展 ID 中 torque 使用 16 位线性映射，数据域中的 16 位值为大端；参数索引和值为小端。所有运控输入必须在所选型号范围内，超限时驱动拒绝构帧，不会静默饱和。

| 型号值 | 型号 | velocity max rad/s | torque max N·m | `iq_ref` max A | kp max | kd max |
| ---: | --- | ---: | ---: | ---: | ---: | ---: |
| 0 | RS00 | 33 | 14 | 16 | 500 | 5 |
| 1 | RS01 | 44 | 17 | 23 | 500 | 5 |
| 2 | RS02 | 44 | 17 | 16 | 500 | 5 |
| 3 | RS03 | 20 | 60 | 43 | 5000 | 100 |
| 4 | RS04 | 15 | 120 | 90 | 5000 | 100 |
| 5 | RS05 | 50 | 5.5 | 11 | 500 | 5 |
| 6 | RS06 | 50 | 36 | 57 | 5000 | 100 |

所有型号 position 范围为 `[-12.57, 12.57] rad`。这些是协议编码边界，不代表机械系统允许在全范围或峰值转矩下工作。

注意：UDP 的 TORQUE 操作对 RobStride 进入 current 模式，`torque` 字段实际写入 `iq_ref`，单位 A；只有 IMPEDANCE/运控帧里的 torque 是 N·m。固件按上表拒绝越界电流。RS02 当前手册的参数表给出 16 A，而电气规格处给出 23 A，固件保守采用 16 A；提高前必须向厂商核对具体硬件与固件版本。电流模式没有速度闭环，必须从很小的 Iq 起步，并依赖机械限位、限流和独立急停。

电机端必须处于私有协议模式。协议切换、波特率、ID 和参数保存都会改变非易失配置，当前 UDP 接口刻意没有暴露这些管理命令；如需工装配置，应直接调用 C 驱动 API，并在无负载条件下单独验证。

## 中科米点六维力传感器

实现文件：`App/Src/force_sensor.c` 和 `App/Inc/force_sensor.h`。依据工作区《中科米点六维力传感器力控通信协议 RS485 V1.4》。电气参数为 9–24 V、RS485、默认 460800、8N1。

帧格式：

```text
AA 55 | command | payload (0..N) | 0D 0A
```

解析器支持分段输入、噪声重同步、固定 24 字节测量、16 字节 SN、可变长度 ASCII 回复，以及数据中的任意 `0D/0A` 字节。USART6 RX 使用 4096 字节循环 DMA（约容纳 141 ms 的 1 kHz 数据），主循环持续消费，不在中断里解析 float。USART6 错误中断只标记故障；HAL 完成 DMA 中止后，主循环重启 DMA、清空半帧解析状态并使旧力数据失效，下一帧有效测量再恢复有效位。最后一帧合法力数据超过 1 s 未更新时，有效位也会自动清除。

手册表格写“IEEE-754 大端”，但同一手册的明确线例 `DA 0F 49 40 -> 3.1415925` 对 STM32 内存表示是小端字节序。默认解码遵循具体线例；主工程通过 `APP_FORCE_FLOAT_ORDER` 选择默认线例顺序（0）或字面大端顺序（1），上板时必须用已知方向/已知载荷确认。若六路数值均为极小异常数，应优先检查这个设置。

命令 `0x06` 的 24 字节数据是下次上电响应，不是立即 ACK。命令 `0x04` 成功时的 `Restart please!` ASCII 回复也已支持；传感器波特率重启后生效，主控配置必须一并更新。

遥测中的单位跟随传感器当前模式：`0x33` 为 kg 与 kg*m，`0x34` 为原始电压，`0x35` 为 N 与 N*m。固件不在遥测中附加单位枚举，因此控制端切换模式后必须自行记录当前单位。

## 共通安全语义

- 提交版危险运动已编译开启，但仍要求逐包 ARM 位；台架版本可将 `APP_REMOTE_MOTION_ALLOWED` 设为 0。
- 每个被使能/运动的节点都有 20..5000 ms 看门狗；到期后 eRob 写快速停机控制字 2，RobStride 发送类型 4 停止。
- 已跟踪的 RobStride 节点在 STOP/DISABLE 前不允许更换型号编号，避免反馈缩放和限幅在运行中改变。
- RobStride 的位置、速度、电流和运控命令只在该节点已由本固件成功提交 ENABLE，且最近 250 ms 内报告 Motor mode、无故障时提交；ENABLE 会先使旧反馈失效，条件不满足即停止。
- CAN RTR 帧不会被当作 SDO、反馈、故障或版本数据。
- UDP ACK 表示板端提交成功，不证明执行器动作完成；反馈时间戳、故障位、机械急停和电源状态仍需上位机联合检查。
- UDP 与力传感器可同时运行的前提是使用本工程的 USART6 外置 RS485 方案；板载 USART2_TX 与 Ethernet MDIO 同占 PA2，不能同时启用。
